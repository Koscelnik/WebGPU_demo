Analýza moderného rozhrania WebGPU a porovnanie s WebGL

WebGPU vs. WebGL: Generačný skok v grafických API na webe

WebGL (založený na OpenGL ES 2.0 / 3.0) vznikol v roku 2011 a odzrkadľuje architektúru GPU z prelomu tisícročí. WebGL funguje ako globálny stavový automat s obrovskou réžiou na strane ovládača (CPU overhead) a chýba mu podpora všeobecných výpočtov.

WebGPU je úplne nové nízkoúrovňové rozhranie vyvíjané konzorciom W3C v spolupráci s Apple, Google, Mozilla a Microsoft. Priamo mapuje moderné natívne grafické rozhrania: Vulkan (Linux/Android/Windows), Metal (macOS/iOS) a DirectX 12 (Windows).

Vlastnosť WebGL 2.0 (OpenGL ES 3.0) WebGPU
Podkladové API OpenGL ES 3.0 (historický model) Direct3D 12, Vulkan, Metal
Compute Shadery ❌ Žiadne (iba triky cez fragment shader a framebuffery) ✅ Plná priama podpora (General-Purpose GPU Compute)
Stavový model Globálny mutovateľný stavový automat (State Machine) Nemenné Pipeline State Objects (PSO)
Manažment pamäte Implicitný, ovládač odhaduje zarovnanie a synchronizáciu Explicitný cez GPUBuffer, mapovanie a flags
Jazyk shaderov GLSL ES (OpenGL Shading Language) WGSL (WebGPU Shading Language)
Viacvláknovosť Iba na jednom hlavnom vlákne (obmedzený OffscreenCanvas) Asynchrónne enkodovanie príkazov z viacerých Web Workerov
Réžia CPU ovládača Vysoká (validácia stavu pri každom drawArrays) Minimálna (validácia prebieha vopred pri zostavení PSO)

1. Explicitné pamäťové buffery

Vo WebGL programátor nevedel, kde presne je pamäť alokovaná ani aké obmedzenia má hardvér. WebGPU vyžaduje explicitné určenie účelu a alokácie pri vytváraní buffera: 

// Vytvorenie explicitného úložného buffera (Storage Buffer) pre bunky:
const cellBuffer = device.createBuffer({
  label: "Cell-Buffer-Storage",
  size: totalCells * Uint32Array.BYTES_PER_ELEMENT,
  usage: GPUBufferUsage.STORAGE | GPUBufferUsage.COPY_DST | GPUBufferUsage.COPY_SRC
});
  • GPUBufferUsage.STORAGE: Umožňuje priamy čítací a zapisovací prístup zo shaderov (ako pole štruktúr alebo primitívnych typov v pamäti VRAM).
  • GPUBufferUsage.UNIFORM: Rýchla vyrovnávacia pamäť s prísnym 16-bajtovým zarovnaním pre globálne parametre (napr. rozmery mriežky, farby).
  • GPUBufferUsage.COPY_DST a MAP_READ / MAP_WRITE: Zabezpečuje bezpečný prenos dát medzi RAM (CPU) a VRAM (GPU) bez nepredvídateľných blokovaní renderovacieho vlákna.
  • Ping-Pong buffering: Pre Conway's Game of Life využívame 2 explicitné buffery (Buffer A a Buffer B). Compute shader číta stav z jedného buffera a zapisuje novú generáciu do druhého, čím sa zabraňuje race conditions bez potreby zámkov.

2. Pipeline State Objects (PSO)

V starom WebGL ste pred vykreslením volali sériu príkazov: gl.useProgram(...), gl.bindBuffer(...), gl.enable(gl.BLEND), gl.blendFunc(...). Ovládač grafickej karty musel pri každom volaní overovať, či je kombinácia týchto prepínačov platná pre hardvér, čo spôsobovalo vysokú latenciu a zadrhávanie snímok (micro-stuttering).

WebGPU namiesto toho zavádza nemenné (immutable) Pipeline State Objects: 

// Zostavenie Compute Pipeline vopred:
this.computePipeline = device.createComputePipeline({
  layout: 'auto',
  compute: {
    module: computeShaderModule,
    entryPoint: 'main'
  }
});

// Zostavenie Render Pipeline s vertex a fragment shaderom, blendovaním a topológiou:
this.renderPipeline = device.createRenderPipeline({
  layout: 'auto',
  vertex: { module: renderShaderModule, entryPoint: 'vs_main' },
  fragment: { module: renderShaderModule, entryPoint: 'fs_main', targets: [{ format }] },
  primitive: { topology: 'triangle-list' }
});

Akonáhle je PSO vytvorené, ovládač ho vopred skompiluje a optimalizuje priamo do strojového kódu GPU. Počas vykresľovacieho cyklu stačí zavolať jediný prepínač pass.setPipeline(pipeline), čo má prakticky nulovú réžiu na CPU.

3. Synchronizácia a Command Encodery

WebGL odosielal príkazy GPU okamžite (Immediate Mode), čím nútil CPU čakať na synchronizáciu stavov. WebGPU funguje na princípe záznamu a dávkového odoslania (Command Recording & Batch Submission):

  1. GPUCommandEncoder: Slúži ako nahrávač grafických a výpočtových inštrukcií do lineárneho poľa v pamäti CPU.
  2. Pass Encodery: Príkazy sa rozdeľujú do logických fáz – computePass (výpočet stavu automatu) a renderPass (vykreslenie pixelov).
  3. Synchronizačné bariéry: WebGPU automaticky rieši závislosti medzi priechodmi (hazard tracking). Ak Compute Pass zapíše do Buffera B a nasledujúci Render Pass z neho číta, ovládač zabezpečí korektnú pamäťovú bariéru bez manuálnych semaforov.
  4. Dávkové odoslanie cez queue.submit(): Všetky príkazy pre celý frame sa odošlú GPU jedným volaním: 
    const commandBuffer = commandEncoder.finish();
device.queue.submit([commandBuffer]);

4. Priama podpora Compute Shaderov v WGSL

Vo WebGL sa všeobecné výpočty (GPGPU) museli simulovať vykreslením 2D obdĺžnika na celú obrazovku a kódovaním dát do farieb (RGBA float textúr).

WebGPU prináša natívne Compute Shadery písané v modernom typovom jazyku WGSL (WebGPU Shading Language). Výpočet sa rozdelí na tisíce paralelných vlákien združených do tzv. Workgroups: 

// Každá pracovná skupina spracováva dlaždicu 16x16 buniek (256 paralelných vlákien)
@compute @workgroup_size(16, 16)
fn main(@builtin(global_invocation_id) id: vec3u) {
  let x = id.x;
  let y = id.y;

  // Priamy prístup do pamäte buniek:
  let index = y * params.width + x;
  let neighbors = countNeighbors(x, y);

  // Paralelné vyhodnotenie pravidla B3/S23 (Conway)
  ...
}
